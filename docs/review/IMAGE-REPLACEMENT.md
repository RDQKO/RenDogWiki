# 이미지 교체 및 종류별 할당

이미지 관리에서 항목을 우클릭해 **이미지 교체** 또는 **추가 이미지 할당**을 선택한다. 한 개를 선택한 상태의 상단 버튼으로도 열 수 있다. 파일 선택·드롭 후 실행하며 별도 확인 단계는 없다. 복원 UI와 복원 PATCH API는 제거했다.

## 이용자 설정

- 홈·문서 공통 헤더의 다크모드 버튼 왼쪽에 **바닐라 큐브 아이콘 → 2D → 3D** 순으로 표시한다.
- 기본 표시는 2D다. 선택한 종류가 할당되지 않은 이미지는 2D로 표시한다.
- 선택 즉시 현재 화면의 관리 이미지를 바꾸고 브라우저에 설정을 저장한다. 다른 탭의 설정 변경도 반영한다. 저장소 사용이 차단돼도 현재 탭에서는 동작한다.
- 모바일은 같은 위치의 작은 선택 메뉴로 접어 헤더 공간을 확보한다.
- 외부 사이트 이미지·플레이어 아바타·정적 홈페이지 로고는 관리 이미지 변환 대상이 아니다.

## 업로드·할당·교체·이동·삭제

| 작업 | 동작 |
| --- | --- |
| 기본 업로드 | 기존 업로드 경로 그대로 2D 이미지로 등록 |
| 추가 이미지 할당 | 기존 이미지 ID에 바닐라·3D 파일 연결. 미할당 종류는 나중에 추가 가능 |
| 이미지 교체 | 모달에서 바닐라·2D·3D 중 변경할 종류를 선택. 선택한 종류만 새 파일로 변경 |
| 문서 삽입 | 기존 2D 기준 주소를 저장. 화면 표시는 이용자 설정에 따라 변환 |
| 이미지 이동 | 논리 이미지의 폴더만 이동. 모든 추가 파일 연결과 기존 문서 주소 유지 |
| 이미지 삭제 | 기본 파일·할당 파일·이전 주소 대응 파일 전체를 S3 삭제 대상으로 수집. DB 연결은 외래 키로 함께 정리 |
| 폴더 삭제 | 하위 폴더의 이미지에도 같은 삭제 규칙 적용 |

같은 이미지 ID·이름·업로더를 유지한다. 문서 JSON을 다시 쓰지 않으며, 본문·인라인 이미지·제목/목차/분류 아이콘·무기/시세 카드·NPC/퀘스트/머리찾기·이미지 선택 창·에디터에서 공통 주소 해석을 사용한다. 모달의 현재·새 파일 미리보기는 이용자 설정과 관계없이 선택한 종류의 실제 파일을 보여준다.

파일은 새 S3 경로에 저장한다. 기존 immutable 캐시를 유지하면서 새 파일 주소로 바뀐다. `image_versions`는 이전 문서 주소를 현재 이미지에 연결하고 삭제할 파일을 추적하는 서버 전용 기록으로 유지한다. 이 기록을 조회해 복원하는 사용자 기능은 제공하지 않는다.

관리자 또는 해당 파일을 올린 작성자만 변경·이동·삭제할 수 있다. 이번 점검에서 이동 API에 누락돼 있던 소유자 검사도 추가했다. 종류 간 동시 변경은 공통 `images.revision`과 행 잠금으로 검사하며, 충돌 시 최신 상태를 다시 확인하도록 409를 반환한다.

파일은 한 개, 최대 3.9MB다. 실제 이미지 디코딩으로 검증하고 필요한 정지 이미지는 WebP로 최적화한다. SVG는 WebP로 변환한다. S3/DB 처리 실패 시 기존 파일 연결을 보존한다. DB 롤백이 확인된 새 파일만 정리하고, COMMIT 결과가 불확실하면 기록을 대조해 실제 사용 중인 새 파일을 삭제하지 않는다.

주소 목록은 서버 렌더링과 화면 이동·새로고침·창 포커스 시 확인한다. 이미지마다 API를 호출하지 않는다. 다른 이용자의 열린 화면에 실시간 푸시하는 기능이나 외부 사이트의 직접 S3 주소를 바꾸는 기능은 포함하지 않는다.

## DB 준비

- `scripts/setup-image-replacements.mjs`: `images.revision`, `images.updated_at`, `image_versions`, `image_variants` 및 인덱스를 멱등적으로 준비한다.
- `scripts/setup-document-save-requests.mjs`: 문서 저장 재시도 식별 기록을 준비한다. 저장 오류의 분석·수정은 [저장 안정화 점검](DOCUMENT-SAVE-RELIABILITY.md)에 기록했다.

기존 커스텀 인증과 서버 Postgres 연결을 사용한다. 새 테이블은 RLS를 켜고 `PUBLIC`·`anon`·`authenticated`의 직접 접근을 차단한다. 공개 이미지 목록은 표시용 주소만 반환한다.

서버 전용 테이블의 기본 거부 상태에서 Supabase의 [RLS Enabled No Policy 정보 알림](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)이 표시될 수 있다. 익명 접근 권한을 열어 해결하지 않는다.

```sh
node --env-file=.env.local scripts/setup-image-replacements.mjs
node --env-file=.env.local scripts/setup-document-save-requests.mjs
```

새 AWS 권한은 필요하지 않다. 기존 `PutObject`, `DeleteObject`, `DeleteObjects`를 사용하며 AWS 키는 서버 환경에만 둔다.

## 2026-11-23 검증

- 격리 PostgreSQL과 S3 명령 모형: 종류별 할당·교체, 2D 대체, 여러 과거 주소의 연결, 본문 보존, 소유자 권한, 동시 변경, DB/S3 실패, COMMIT 응답 유실, 이미지 이동과 하위 폴더의 전체 파일 삭제.
- UI: 파일 드롭·미리보기·하단 버튼, 명시적 줄바꿈, 복원 제거, 409 후 최신 상태 재조회, 설정 유지·다른 탭 동기화, 서버 초기 표시, 주소 목록 요청 경쟁, 브레드크럼 16px·바로가기 24px 크기 회귀 검사.
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:http` 실행.
- 운영 DB에 추가 구조만 적용했다. 전후 이미지 3,227개와 문서 본문 215개의 수·내용 해시가 같았다. 기존 파일의 실제 S3 교체는 수행하지 않았다.
- 실제 AWS 업로드는 테스트용 이미지로 배포 후 확인해야 한다. 자동 테스트에서는 실제 사용자 파일을 변경하지 않았다.

기존 변경의 부작용 점검과 후속 범위는 [변경 범위 보고서](IMAGE-REPLACEMENT-SCOPE.md)에 기록했다.
