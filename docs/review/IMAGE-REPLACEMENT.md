# 이미지 교체 기능

이미지 관리에서 항목을 우클릭해 **이미지 교체**를 선택한다. 한 개를 선택한 상태의 상단 버튼으로도 열 수 있다. 현재 이미지와 새 파일을 비교하고 적용하면 같은 이미지 ID를 유지하면서 새 S3 파일로 전환한다. 문서를 다시 저장할 필요가 없다.

## 동작

- 기존 이름·폴더·업로더를 유지한다. 파일 경로·URL·MIME 형식·변경 버전을 갱신한다.
- 파일은 새 S3 경로에 저장한다. 기존 immutable 캐시를 유지하면서도 새 파일을 요청한다.
- `image_versions`에 과거 파일을 보관한다. 과거 S3/CDN 주소를 현재 파일에 연결하는 작은 목록을 서버 렌더링과 방문/포커스 시 공급한다. 이미지마다 API를 호출하지 않는다.
- 본문·인라인 이미지·제목/목차/분류 아이콘·무기/시세 카드·NPC/퀘스트/머리찾기·선택 창과 에디터에 적용한다. 문서의 크기·높이·정렬과 본문은 변경하지 않는다.
- 복원 화면의 과거 미리보기는 주소 변환을 하지 않아 실제 과거 파일을 보여준다. 복원은 기존 파일을 재사용하며 S3에 다시 업로드하지 않는다.
- 관리자 또는 해당 이미지를 올린 작성자만 교체/복원한다. 실제 DB 계정과 소유자를 서버에서 확인한다.
- 동시 교체는 행 잠금과 단조 증가하는 `revision`으로 검사한다. 충돌 시 409와 최신 상태 재조회 동작을 제공한다.
- S3 업로드나 DB 처리 실패 시 원본을 유지한다. DB 롤백이 확인된 새 파일만 정리한다. COMMIT 결과가 불확실하면 파일을 삭제하지 않고 기록을 대조한다.
- 이미지·폴더 삭제 시 보관된 파일도 삭제 대상에 포함한다. DB에서 이미지가 삭제되면 이력은 외래 키로 함께 정리된다.
- 한 파일 3.9MB 이하. 실제 이미지 디코딩으로 검증한다. 작은 래스터·애니메이션은 유지하고 필요한 정지 이미지는 WebP로 최적화한다. SVG는 WebP로 변환한다. 영상 교체는 이번 기능에 포함하지 않는다.
- 변경 사항은 새 방문·새로고침·창 포커스 시 확인된다. 다른 이용자의 열린 화면에 실시간 강제 갱신을 보내는 기능은 포함하지 않는다.

## DB 준비

`scripts/setup-image-replacements.mjs`가 멱등적으로 `images.revision`, `images.updated_at`과 `image_versions` 및 조회 인덱스를 추가한다. 기존 이미지·문서를 교체하거나 삭제하지 않는다.

앱은 기존 커스텀 인증과 서버 Postgres 연결을 사용한다. 이력 테이블은 RLS를 켜고 `PUBLIC`·`anon`·`authenticated`의 직접 접근을 차단한다. 공개 API는 현재 이미지로 연결되는 주소 목록만 반환하며 변경자는 반환하지 않는다.

서버 전용 테이블이므로 기본 거부를 사용한다. Supabase의 [RLS Enabled No Policy 정보 알림](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)은 이 의도된 상태에서 표시될 수 있다. 직접 API 권한을 열어 해결하지 않는다.

서버 DB 연결을 지정한 환경에서 다음을 실행할 수 있다.

```sh
node --env-file=.env.local scripts/setup-image-replacements.mjs
```

이번 기능에는 새 AWS 권한이 필요하지 않다. 기존 업로드와 같은 `PutObject`, 실패 정리를 위한 `DeleteObject`를 사용한다. AWS 키는 서버 환경에만 둔다. 브랜치의 코드를 배포해야 관리 메뉴와 API가 활성화된다.

## 검증

- `npm test`: 격리 Postgres에 실제 트랜잭션을 실행하고 S3 명령은 가짜 저장소 경계로 확인한다. 여러 번 교체, 복원, URL 호환, 원문 보존, 권한, 실패, 동시 수정, COMMIT 응답 유실, 보관 파일 삭제를 포함한다.
- UI 검증: 파일 드롭·미리보기·하단 버튼·409 후 재확인·복원·초기 서버 표시·변경 목록 요청 경쟁 및 다수 이미지에 공통 목록을 적용하는지 확인한다.
- `npm run typecheck`, `npm run lint`, `npm run build`.
- `npm run test:http`: 로컬 Next 서버와 격리 DB에서 로그인·이력 조회·복원·충돌·공개 주소 갱신을 확인한다. 실제 S3 파일은 건드리지 않는다.
- 최종 운영 점검: 배포 후 테스트용 이미지를 업로드해 교체하고 문서·인라인·카드 표시, 새로고침, 복원을 확인한다. 실사용 이미지로 시험 교체하지 않는다.

주소의 실제 파일 바이트는 문서 JSON에 복사되지 않는다. 외부 사이트가 과거 S3 URL을 직접 사용하는 경우 그 사이트까지 자동 변경하는 기능은 아니다.

## 2026-11-23 검증 결과

- 자동 테스트 75개, 실제 HTTP 검사 42개 통과.
- TypeScript 검사·프로덕션 빌드 통과. lint 오류 없음. 기존 Hook·이미지 관련 경고는 남아 있다.
- 운영 DB에 필요한 추가 구조를 설치하고 이력 테이블의 RLS 및 직접 접근 차단을 확인했다.
- 전후 비교에서 기존 이미지 3,226개의 이름·파일 경로·URL·형식과 문서 211개의 본문은 동일했다. 실제 S3 파일을 교체하지 않았다.
- 브랜치 배포 후 테스트 이미지로 실제 AWS 업로드·표시·복원을 확인해야 한다. 자동 테스트의 S3 요청은 가짜 클라이언트로 검증했다.
