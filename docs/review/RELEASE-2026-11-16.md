# 2026-11-16 로그인 권한·문서 저장 수정

사용자의 main 반영·운영 배포 요청에 따라 Claude 디자인 브랜치 `40001e1` 위에서 두 오류를 수정했다. 이전 기술 점검·기능 수정·Claude 디자인 변경을 포함하여 하나의 release PR로 main에 통합한다. 운영 DB 스키마 변경은 없다.

## 로그인 직후 권한 인식

로그인 API는 쿠키만 발급하고 로그인 페이지가 영속적인 AuthProvider를 갱신하지 않았다. 메뉴는 별도로 `/api/auth/me`를 조회하여, 메뉴와 관리 레이아웃이 서로 다른 권한 상태를 쓰고 있었다. 기존 AuthProvider에는 초기 요청·강제 갱신의 응답 순서를 보호하는 장치도 없었다.

- 로그인 응답에 DB에서 확인한 사용자·역할을 담고, 페이지 이동 전에 공용 상태를 갱신한다. 비밀번호·해시는 응답하지 않는다.
- 메뉴와 관리 레이아웃은 같은 AuthProvider를 사용한다. 메뉴의 중복 권한 상태·조회 로직을 제거한다.
- 로그인·로그아웃·새 갱신 시 이전 요청을 취소하고 세대를 검사하여 늦게 도착한 응답을 무시한다.
- 초기 확인 effect의 의존성을 안정화하여 hydration 후 불필요한 재요청을 막는다.
- DB 읽기 오류는 제한적으로 재시도한다. 확인 실패는 503으로 구분하고, 프런트의 기존 로그인·역할을 guest로 덮어쓰지 않는다.
- 역할을 확인할 수 없을 때는 권한 부족으로 단정하지 않고 관리 안내 창에서 다시 확인할 수 있다.
- 모든 쓰기 API의 현재 DB 계정·역할 검사는 계속 적용한다. UI 상태 보존이 서버 권한 검사를 대신하지 않는다.

## 문서 저장

실패 가능 경로를 코드와 격리 DB 테스트로 확인하여 수정했다. Vercel runtime 로그 접근은 현재 연결의 팀 권한 부족(403)으로 불가능했으므로, 과거 운영 504의 단일 원인이 확정됐다고 주장하지 않는다. 조회 당시 운영 DB에 대기 중인 잠금이나 idle-in-transaction 연결은 발견하지 못했다.

- 편집기는 `fresh=1`로 본문과 수정 시각을 DB에서 함께 읽는다. 일반 열람의 공유 캐시는 유지한다. 오래된 캐시가 불필요한 409를 유발하는 경로를 차단한다.
- 저장 시 실제 Slate 본문과 태그 입력의 스냅샷을 사용하고, 성공 응답의 ID·수정 시각을 확인한다.
- 저장은 기존 전역 gate를 공유 잠금으로 사용하고, 카테고리별 배타 잠금으로 제목 중복 검사·순서를 보호한다. 카테고리 변경·문서 삭제의 기존 전역 배타 잠금과는 충돌하므로 구조 변경과의 안전성은 유지한다.
- 검색 섹션 계산은 잠금 획득 전에 수행한다. 메타·본문·검색 인덱스의 단일 트랜잭션은 유지한다.
- 잠금 대기 3초·쿼리 12초·idle-in-transaction 20초의 상한과 함수 제한 30초를 사용한다.
- PostgreSQL이 확실히 롤백한 55P03/40P01/40001만 1회 재시도한다. 커밋 여부가 불명확한 연결 실패는 자동으로 쓰기를 반복하지 않는다.
- 커밋 후 캐시 무효화 실패는 성공 응답을 실패로 바꾸지 않는다. 활동 로그는 Next.js `after()`로 응답 이후 처리한다.
- 실제 동시 편집 충돌은 계속 409로 막고, 지연·연결 실패는 안내하면서 편집 내용을 유지한다.
